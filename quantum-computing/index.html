Quantum Computing

error-corrected quantum computers with far fewer qubits, and where the field stands

Quantum computers make errors constantly, so a machine that runs long, useful programs has to correct its own mistakes as it computes. The leading approach is expensive: each reliable logical qubit is built from hundreds to thousands of noisy physical qubits. Our group designs error-correcting codes that store many logical qubits in far fewer physical ones, and works out how to compute with them.

28 times fewer qubits at the same code distance

Code distance

Our [[90,21,11]] code: 90 data qubits hold 21 logical qubits.

Surface code at the same distance 11: one 11 × 11 patch per logical qubit, 2,541 data qubits in all.

Data qubits only: each design needs roughly as many extra qubits again to measure its checks. A code of distance d can correct any (d − 1)/2 errors, rounded down. Distance is a first measure of protection; the full comparison under realistic noise is in the papers.

There is a catch. Packed this tightly, logical qubits overlap on the same physical qubits, so acting on one without disturbing the others becomes the hard part. Much of our recent work is about that catch.

How many qubits does a useful quantum computer need?

The field’s standard yardstick is factoring a 2048-bit RSA number with Shor’s algorithm. Published estimates have fallen from about a billion physical qubits in 2012 to under 100,000 today, or about 13,000 for a machine willing to run for decades. The two most recent drops, both in 2026, came from replacing the surface code with high-rate quantum LDPC codes, the family of codes we design.

These are designs on paper: no machine this large exists yet, and runtimes range from hours to decades. Still, the trend is why high-rate codes have moved from theory papers into company roadmaps.

Compiler

Simulated at full scale. Full designs and resource estimates exist; compilers for qLDPC machines are just appearing.

Decides which logical qubits meet, in what order, and when to call for magic states, so that a program runs in as little time and space as possible.

  • Compile real programs onto high-rate code blocks: which logical qubits share a block, and when they move.
  • Report qubits and runtime together, under common assumptions, so that designs can be compared.
  • Find useful applications beyond factoring that fit early fault-tolerant machines.

Memory

Shown on small devices. Small qLDPC codes run on superconducting and trapped-ion hardware; no large qLDPC memory exists yet.

Holds most logical qubits most of the time, correcting errors every cycle. High-rate codes make it the cheapest part of the machine per logical qubit.

Open problems

  • Find the best codes at realistic sizes, where rate, distance, check weight and block size pull against each other.
  • Certify the distance of large codes, a computationally hard problem in general.
  • Keep the full distance during measurement circuits, and cope with atom loss and leakage.
  • Fit long-range checks onto chips and atom arrays without slowing the cycle.

Logic unit

Simulated at full scale. Logic on hardware so far uses surface codes or small codes.

Carries out logical operations, mostly by code surgery: temporarily attaching extra qubits that measure chosen logical operators. In a high-rate block it must reach one logical qubit without disturbing the rest.

Progress across the field

  • Lower-overhead surgery for qLDPC codes, with bridges that join gadgets for joint measurementsIBM, 2024Theory
  • Logical measurements by gauging logical operatorsWilliamson and Yoder, 2024Theory
  • Extractors: one fixed gadget that can measure any logical Pauli productHe, Cowtan, Williamson and Yoder, 2025Theory
  • Many logical measurements in parallel by code surgeryCowtan, He, Williamson and Yoder, 2025Theory
  • Reusable surgery gadgets, tested on 15 billion simulated operationsCaltech and Oratomic, 2026Theory
  • Logical entanglement by transversal gates and lattice surgery, on up to 448 atomsHarvard-led team, 2025Experiment

Open problems

  • Measure any chosen logical qubits cheaply, quickly and in parallel. Surgery costs grow with the weight of the logical operator, and each measurement takes about d rounds.
  • Verify that large gadgets are fault tolerant; estimating their fault distance becomes prohibitive for big blocks.
  • Find fast logic for qLDPC codes: transversal, single-shot or symmetry-based gates.

Magic-state factory

Shown on small devices. Logical distillation and cultivation have run on neutral-atom and superconducting hardware.

Easy operations alone cannot run every algorithm. The factory prepares special magic states and feeds the logic unit one for each hard gate, such as a T gate.

Progress across the field

  • Magic state cultivation: magic states nearly as cheap as two-qubit gatesGidney, Shutty and Jones (Google), 2024Theory
  • Logical magic state distillation on neutral atomsQuEra, 2024Experiment
  • Cultivation tested on a superconducting processorRosenfeld et al., 2025Experiment
  • Magic states made directly inside finite qLDPC codesMenon et al., 2025Theory
  • Magic states injected into every logical qubit of a block at onceCaltech and Oratomic, 2026Theory

Open problems

  • Make magic states as fast as a high-rate processor consumes them, without a factory larger than the memory.
  • Get them into qLDPC blocks efficiently and in parallel.
  • Turn constant-overhead distillation and transversal non-Clifford gates for qLDPC codes from theory into practical protocols.

Decoder

Shown on small devices. Real-time decoding has run on hardware for surface codes; qLDPC decoders look fast enough on paper.

A classical co-processor that receives check results every cycle and infers which errors occurred. It has to keep pace with the machine, or the computation stalls.

Progress across the field

  • Real-time decoding during a below-threshold surface-code experimentGoogle Quantum AI, 2024Experiment
  • Relay-BP: belief propagation accurate enough for real-time qLDPC memoryIBM, 2025Theory
  • A staged decoder reaching about 10−11 logical errors per round in simulationCaltech and Oratomic, 2026Theory

Open problems

  • Decode during logical operations, not just storage, faster than the machine's reaction time.
  • Scale to tens of thousands of qubits on practical classical hardware.
  • Handle realistic noise: correlated errors, leakage and atom loss.

Physical qubits and connectivity

Shown on small devices. Hundreds of qubits run below threshold, thousands can be held, and long-range links work on small chips.

High-rate codes need checks that connect distant qubits. Atom arrays move atoms, superconducting chips route long couplers through extra layers, and ion traps shuttle ions between zones.

Progress across the field

  • Error rates below the surface-code threshold on a superconducting chipGoogle Quantum AI, 2024Experiment
  • A universal fault-tolerant architecture on up to 448 atomsHarvard-led team, 2025Experiment
  • Over 6,100 coherent atoms held in one arrayCaltech, 2024Experiment
  • Two cryogenic modules joined, toward IBM's 2029 machineIBM, 2026Experiment

Open problems

  • Grow from hundreds to tens of thousands of qubits while keeping error rates near 0.1% or lower.
  • Make long-range connectivity fast and reliable: atom-array cycles of milliseconds must shrink, and multilayer chips must be built at scale.
  • Understand noise beyond simple models, including correlated bursts and leakage.

Our work in detail

Error-correcting codes

The surface code stores one logical qubit per patch, and each patch grows with the square of the distance. High-rate quantum LDPC codes break that pattern: each check still involves only a handful of qubits, but checks can reach across the block, so one block can hold dozens or hundreds of logical qubits. The hard part is that block size, encoding rate, distance and check weight all pull against each other.

  • Design principles for ultra-high-rate quantum codes (2026, with Koki Okada, Nishad Maskara, Kenta Kasai and Hengyun Zhou) turns these trade-offs into design rules. One finding: at a realistic 0.1% physical error rate, heavier checks are often worth it, because they buy larger distance in a small block. The resulting codes, such as [[90,21,11]], [[140,31,15]] and [[200,43,20]], need only a few data qubits per logical qubit.
  • Designing group-valued codes (2026) builds codes such as [[1088,128,22]] and [[1024,256,24]] with a complete, regular basis of logical operators about as light as the distance allows, and shows why this is impossible for a common class of codes built on odd-order groups.
  • Lifting lifted-product codes (2026, with Yuta Hirasaki) grows a code into a family that keeps its local structure. It finds codes with better parameters than previously reported, and takes a first step toward code families with a well-defined large-size limit.

Logical operations

Packing many logical qubits into one block creates a new problem. To compute, you need to know where each logical qubit lives, how it is labeled, and how to act on it without disturbing its neighbors. For Abelian lifted-product codes, which include many of the best high-rate designs, the row-reduction shortcut that works for simpler product codes can fail.

  • Logical spectroscopy (2026) fixes this for Abelian lifted-product codes. Like a prism splitting light into colors, it splits the code’s algebra into small independent pieces, solves each one, and reassembles a complete, labeled set of logical operators. It has been applied to codes with up to 5,000 physical qubits.
  • Full regular low-weight bases (2026) introduces the frame width: the smallest weight limit that still allows a complete canonical set of logical operators. Lighter operators make logical operations cheaper, so frame width belongs next to distance in resource estimates.
  • Lifting lifted-product codes (2026, with Ph.D. student Yuta Hirasaki) shows that surgery gadgets, the standard way to measure logical qubits, carry over across a family of codes, sometimes at lower cost.

Next, with support from a Microsoft Quantum Pioneers award, we are building on logical spectroscopy toward hardware-aware compilation for qLDPC codes.

Hardware and dynamics

Codes have to run on real machines, and real machines suggest new codes.

  • Two qubits per atom (npj Quantum Information 2024): with Jacob Covey’s group at Illinois, an architecture that stores two qubits in each ytterbium-171 atom, so error correction needs fewer two-atom gates.
  • Stable Floquet codes (Phys. Rev. Lett. 2024): Floquet codes protect qubits with a repeating cycle of simple two-qubit measurements. We showed that the dynamical topological order they create survives perturbations.
  • Decoding measurement-prepared states (2022): measurements can create long-range entangled states quickly, and the outcomes can be decoded by classical computation instead of repeating the experiment exponentially many times.

Noise and thresholds

Code families typically have an error threshold: below a certain noise level, bigger codes protect better; above it, no decoder can recover the information. We study thresholds as phase transitions, like water freezing, using information-theoretic quantities that do not depend on any particular decoder. This connects to our broader work on mixed-state phases of matter.

  • Exact coherent information for the toric code (Phys. Rev. Lett. 2025) gives the first exact formula for how much information survives noise, tying the code’s fundamental threshold to the random-bond Ising model. A follow-up (Phys. Rev. A 2025, with Ryotaro Niwa) extends this to all CSS codes.
  • Hierarchy of Rényi coherent information (2026, with Ph.D. student Akash Vijay and Luis Colmenarez) proves that, for independent Pauli noise, the computable Rényi versions used across the field are ordered by their Rényi index, and gives them an operational meaning.
  • Information critical phases (2025, with Akash Vijay) finds, in noisy ZN toric codes with N > 4, a whole intermediate phase in which a fraction of the stored information survives.
  • Beyond standard codes: error thresholds of SYK codes (Phys. Rev. B 2026, with Jaewon Kim and Ehud Altman) and approximate error correction at chiral topological edges (2026, with former postdoc Bowen Shi).

Key terms

Physical qubit
One quantum bit in hardware: an atom, an ion or a superconducting circuit. Each one makes errors.
Logical qubit
One qubit's worth of information spread over many physical qubits, so that errors can be detected and undone.
Code distance d
The smallest number of single-qubit errors that can change the stored information without being detected. A code of distance d corrects any (d − 1)/2 errors, rounded down.
[[n, k, d]]
Shorthand for a code that stores k logical qubits in n physical qubits at distance d. A surface-code patch is [[d², 1, d]].
Encoding rate
Logical qubits per data qubit, k/n: 1/121 for a distance-11 surface code, 21/90 for our [[90,21,11]] code.
qLDPC code
Quantum low-density parity-check code. Each check involves only a few qubits and each qubit only a few checks, but checks may connect distant qubits.
Check weight
How many qubits one check involves: 4 in the surface code, 6 to 10 in the high-rate codes on this page.
Threshold
For a family of codes, the physical error rate below which making the code bigger makes it better.
Decoder
The classical algorithm that reads the check results and infers a correction. In a real machine it has to keep up with the stream of results.
Code surgery
Measuring logical qubits by temporarily attaching extra qubits and checks to a code; a leading way to compute with qLDPC codes.
Magic state
A special resource state that, combined with the easy operations, makes a quantum computer universal.
